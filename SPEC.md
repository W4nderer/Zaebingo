# Zaebingo: спецификация

Веб-приложение (PWA) для музыкального бинго на 90 треков. Генерирует карточки для печати и проверяет их во время игры: один ведущий вносит номера сыгранных треков, несколько проверяющих сканируют QR на карточках.

Первая версия работает без бэкенда: приложение состоит из статических файлов, данные игры хранятся на телефонах.

Состояние документа: план, код ещё не написан. Нерешённое собрано в разделе «Открытые вопросы».

## Как проходит игра

1. Ведущий называет номер и включает песню.
2. Игроки слышат песню и ищут её на бумажных карточках: у каждого игрока своя, и ещё одна общая у команды.
3. Ведущий вносит номер в приложение.
4. Игрок или команда, выполнившие условие победы, объявляют бинго.
5. Проверяющий сканирует QR на карточке и получает вердикт.

## Платформа и распространение

- PWA: один код для Android и iOS, устанавливается на экран телефона по ссылке.
- Публикация в Google Play и App Store не нужна, приложение для себя и знакомых.
- Сервера нет. Статические файлы приложения размещаются на GitHub Pages, репозиторий публичный. Табличка с треками в репозиторий не попадает.
- После первой загрузки приложение работает офлайн. Сеть нужна только для того, чтобы забрать табличку.
- Генерация карточек рассчитана на работу с компьютера, ведение игры и проверка — с телефона.
- Интерфейс на русском и английском.

## Роли

### Ведущий

- Создаёт игру на своём телефоне.
- Вводит номер трека (1–90). Приложение сразу показывает исполнителя и песню из таблички.
- Может отменять ввод, в том числе несколько последних номеров подряд.
- Видит список уже сыгранных треков.
- Повторный ввод уже сыгранного номера не принимается.
- В игре только один ведущий.
- Может проверять карточки сам, на том же телефоне.
- Передаёт состояние игры проверяющим (см. «Передача состояния игры»).

### Проверяющий

- Получает состояние игры от ведущего. Проверяющих может быть несколько.
- Вносить номера не может.
- Сканирует QR на карточке игрока или команды и видит карточку с подсвеченными закрытыми клетками и вердикт: какое условие победы выполнено либо чего не хватает.
- На экране проверки всегда видно, сколько треков сыграно в его копии состояния и какой был последним, чтобы заметить устаревшие данные.

## Табличка с треками

- Лежит в Google Sheets с доступом на чтение для всех, у кого есть ссылка. Приложение забирает её само и хранит копию на устройстве.
- 90 строк, по одной на трек.
- Столбцы:

| Столбец | Назначение |
| --- | --- |
| `№` | Номер трека, 1–90. Его называет и вводит ведущий |
| `Исполнитель` | Показывается ведущему при вводе номера |
| `Песня` | Показывается ведущему при вводе номера |
| `Текст для карточки` | Печатается в клетке карточки как есть |

- При генерации приложение проверяет, что `Текст для карточки` заполнен во всех 90 строках и не повторяется. Иначе игрок не поймёт, какую клетку закрывать.
- Идентификатор серии карточек — хеш пар «`№` → `Текст для карточки`», то есть того, что напечатано на бумаге. Если эти пары изменили после печати, приложение увидит несовпадение с идентификатором в QR карточки и предупредит. Правка столбцов `Исполнитель` и `Песня` идентификатор не меняет.

Точные названия и порядок столбцов уточняются по примеру таблички.

## Карточки

Игроки объединены в команды. Карточки двух типов:

| Тип | Сетка | Клеток | Размер | У кого |
| --- | --- | --- | --- | --- |
| Карточка игрока | 4×5 | 20 | А4 | У каждого игрока своя |
| Командная карточка | 5×5 | 25 | А5 | Одна общая на команду |

- Все клетки заполнены, пустых нет.
- Треки для карточки выбираются случайно из 90 и раскладываются по клеткам случайно.
- В клетке печатается `Текст для карточки`. Номера треков на карточке не печатаются.
- Размер шрифта подбирается под клетку автоматически. Если текст не помещается даже минимальным шрифтом, генератор предупреждает.
- Шрифт любой свободный с кириллицей, встраивается в PDF.
- Все карточки одного типа в серии различаются набором треков; другой раскладки того же набора недостаточно.
- Серия после генерации не сохраняется, перепечатка отдельной карточки не предусмотрена.
- На карточке есть QR и номер карточки.
- Карточка игрока печатается на листе А4, командная имеет размер А5.
- Командные карточки выводятся в PDF по две на лист А4 под разрезку, с линией реза посередине.
- При генерации серии задаётся количество карточек каждого типа.
- Результат генерации — PDF для печати.

### Шаблон оформления

- У карточки есть шаблон размером с саму карточку (А4 для игрока, А5 для команды): лого, дополнительная информация и прочее оформление. Он накладывается на клетки.
- Шаблон загружается в генератор файлом. У каждого типа карточки свой шаблон.
- В настройках серии для каждого типа задаются прямоугольник, в который вписывается сетка, и место для QR с номером карточки. Задаются цифрами в миллиметрах, рядом показывается превью.
- Генератор должен работать в обоих случаях: когда линии сетки нарисованы в самом шаблоне и когда их рисует приложение.
- Предпочтительный формат шаблона: PNG с прозрачностью в 300 dpi (около 3508×2480 пикселей для А4 и 2480×1748 для А5), PDF или SVG.

### QR-код карточки

- В QR зашиты идентификатор серии, тип карточки, её номер и номера треков с их позициями в сетке.
- Проверка не зависит от базы карточек: проверяющему достаточно QR и списка сыгранных номеров.
- Текст клеток для показа на экране берётся из копии таблички на устройстве.

## Условия победы

- **Командная карточка:** закрыты все 25 клеток.
- **Карточка игрока:** несколько этапов по возрастанию; проверка показывает высший выполненный этап. Сами этапы ещё не определены (см. «Открытые вопросы»).

Набор условий задаётся отдельно для каждого типа карточки, чтобы его можно было менять без переделки проверки.

## Передача состояния игры

Бэкенда нет, поэтому телефоны не синхронизируются сами. Состояние игры — это идентификатор серии и список сыгранных номеров; оно занимает несколько десятков символов и целиком помещается в QR или ссылку.

- **QR с экрана ведущего.** Телефон ведущего показывает QR с текущим состоянием. Проверяющий сканирует его и получает актуальный список. Работает без сети.
- **Ссылка.** Ведущий нажимает «Поделиться» и отправляет ссылку с состоянием в общий чат. Проверяющий открывает последнюю ссылку.

Ограничение: копия у проверяющего устаревает, как только ведущий внёс следующий номер. Перед проверкой её надо обновить одним из двух способов.

Логика игры пишется отдельно от способа передачи состояния, чтобы позже можно было добавить автоматическую синхронизацию через бэкенд (Firebase или скрипт в Google Sheets), не переписывая остальное.

## Этапы работы

1. Чтение таблички и генератор карточек с PDF, включая шаблон оформления.
2. Экран ведущего: ввод номера, показ исполнителя и песни, список сыгранного, отмена. Проверка карточек по QR на том же телефоне.
3. Передача состояния проверяющим через QR и ссылку.
4. Доработки: история игр, несколько серий.
5. При необходимости: автоматическая синхронизация через бэкенд.
